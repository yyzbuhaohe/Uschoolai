# 已知问题 / 待办

更新于 2026-02 配音题落地后。

## 已经解决的

- ✅ 单选题 / 多选题 / 判断题：转写 → 模型作答 → 按序号点
- ✅ 填空题：`__BLANK__` 占位 → 前后词在原文里定位（`solveBlank`，已内联进 run-all.js）
- ✅ 排序题：证据句定序（模型先给每条陈述找证据句，再按时间戳排），实测 4/4、100 分
- ✅ 讨论/评论：生成英文发帖
- ✅ 跟读题：TTS 回灌麦克风，88~94
- ✅ 说话题：口稿 → TTS → 回灌，90+
- ✅ 配音题：接管页面自带示范音，逐句回灌，82~85
- ✅ 上传题：塞彩蛋 PDF
- ✅ 翻节：必修锁链判断，遇锁停下
- ✅ 僵尸遮罩自动清理（会跳过真正的确认弹窗）

## 还能更好

### 配音题
- 目前 5 句里通常 4 句能到 82~85，偶尔有一句掉到 40 出头 —— 是配段起点偏了（whisper 分段和实际朗读位置有几十毫秒到半秒的差）。
- 改进方向：用页面示范音的时长反推起点，或者对同一句做多段候选打分。

### 排序题
- 陈述被大幅改写（不是原文复述）时，证据句可能找偏，这时分数会掉到 60 左右。

### 选择题
- 题目本身有歧义时模型会错，尤其"下列哪项不正确"这种。

### 口语题
- 页面只认第一次作答的分，录坏了也覆盖不了，只能换节重来。

## 已知限制

- Python 3.13 装不上 faster-whisper，必须 3.11 / 3.12
- 一个调试端口只能挂一个会话，不能并发
- Chrome 组策略锁了扩展权限时，Tampermonkey 无效，必须用 `potato-watch.js` 注入

## 和其他题型的关系

配音题的所有代码在 `dub.js` + `dub-hook.js` 两个独立文件里，run-all 只在检测到 `.question-video-dub-pc` 时把这一屏交给 `dub.js`（子进程）处理，其他题型完全走原来的分支，互不影响。
